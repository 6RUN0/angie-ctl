# angie-ctl

Простой скрипт для управления HTTP-конфигурациями и модулями Angie, аналогичный a2enconf/a2enmod для Apache.
Позволяет включать, отключать и просматривать доступные/включённые конфиги и модули через симлинки.

## Возможности

- Включение/отключение HTTP-конфигов и модулей по имени
- Запрос состояния (`status`) и очистка осиротевших симлинков (`prune`)
- Опционально перезагрузить Angie (`--reload`) и откатить батч, если проверка
  конфигурации провалилась (`--rollback`)
- Просмотр доступных и включённых конфигов/модулей
- Отклоняет небезопасные имена (path traversal) и не удаляет файлы, не являющиеся симлинками

## Использование

```text
./angie-ctl.sh [options] {httpconf|mod} {en|dis|ls|ls-available|ls-enabled|status|prune} [name ...]
```

Команды:

- `en`, `dis` — включить/отключить указанные конфиги (создание/удаление симлинков)
- `status` — печатает `[on ]`/`[off]` по каждому имени; код возврата 0 только если все включены
- `prune` — удалить все осиротевшие включённые симлинки (без источника в available)
- `ls` — список доступных с маркерами `[on ]`/`[off]`/`[orphan]`
- `ls-available`, `ls-enabled` — список одной директории

Опции (указывайте каждую отдельно; `-nT` не разбивается на `-n -T`):

- `-n`, `--dry-run` — показать, что изменили бы `en`/`dis`/`prune`, ничего не меняя
- `-T`, `--no-test` — пропустить проверку `angie -t`, которая иначе выполняется после батча
- `-r`, `--reload` — перезагрузить Angie (`$ANGIE_RELOAD_CMD`) после успешного батча
- `--rollback` — если проверка конфигурации после батча провалится, откатить изменения
  этого запуска (нельзя сочетать с `--no-test`)
- `-h`, `--help`, `help` — показать справку и выйти

Переменные окружения:

- `ANGIE_ETC` — корень конфигов (по умолчанию `/etc/angie`; должна быть абсолютным путём без сегментов `..`)
- `ANGIE_BIN` — бинарь для проверки конфигурации (по умолчанию `angie`). Проверка
  выполняется с фиксированным `PATH` (`/usr/sbin:/usr/bin:/sbin:/bin`); чтобы
  запустить бинарь вне этих каталогов, укажите абсолютный путь. Считайте
  `ANGIE_BIN`/`PATH` чувствительными к доверию, если инструмент оборачивается
  в sudo или CI.
- `ANGIE_RELOAD_CMD` — команда перезагрузки для `--reload` (по умолчанию `$ANGIE_BIN -s reload`),
  выполняется с тем же фиксированным `PATH`

### Примеры

Включить конфиг:

```sh
./angie-ctl.sh httpconf en drupal
./angie-ctl.sh httpconf en drupal.conf
```

Отключить конфиг:

```sh
./angie-ctl.sh httpconf dis drupal
```

Включить модуль:

```sh
./angie-ctl.sh mod en geoip
```

Отключить модуль:

```sh
./angie-ctl.sh mod dis geoip
```

Проверить, включены ли конфиги (код возврата 0 только если все включены):

```sh
./angie-ctl.sh httpconf status drupal
./angie-ctl.sh mod status geoip
```

Включить и перезагрузить за один шаг или откатить при провале проверки:

```sh
./angie-ctl.sh --reload httpconf en drupal
./angie-ctl.sh --rollback mod en geoip
```

Удалить осиротевшие включённые симлинки (без источника в available-директории):

```sh
./angie-ctl.sh httpconf prune
./angie-ctl.sh -n httpconf prune   # сначала предпросмотр
```

Посмотреть включённые конфиги/модули:

```sh
./angie-ctl.sh httpconf ls
./angie-ctl.sh mod ls
```

Посмотреть все доступные конфиги/модули:

```sh
./angie-ctl.sh httpconf ls-available
./angie-ctl.sh mod ls-available
```

Посмотреть все включённые конфиги/модули:

```sh
./angie-ctl.sh httpconf ls-enabled
./angie-ctl.sh mod ls-enabled
```

## Директории

- Доступные конфиги: `/etc/angie/http-conf-available.d`
- Включённые конфиги: `/etc/angie/http-conf.d`
- Доступные модули: `/etc/angie/modules-available.d`
- Включённые модули: `/etc/angie/modules.d`

Корневая директория конфигов по умолчанию — `/etc/angie`; её можно
переопределить переменной окружения `ANGIE_ETC` (должна быть абсолютным путём).

## Требования

- POSIX `sh`
- Достаточные права для создания/удаления симлинков в конфиг-директориях Angie

## Примечания

- Имена можно указывать с расширением `.conf` или без него
- Имя должно быть одним компонентом пути; значения с `/` (а также `.`/`..`) отклоняются
- `dis` удаляет только симлинки — реальный файл в директории включённых конфигов никогда не удаляется
- Битые (висячие) симлинки по-прежнему отображаются в списке и могут быть отключены
- `ls` помечает включённую запись без источника в available-директории как `[orphan]`;
  `prune` удаляет такие осиротевшие симлинки (реальные файлы пропускаются)
- `status` возвращает 0 только когда включены все запрошенные имена, поэтому удобно использовать в скриптах

## Проверка конфигурации

После успешного батча `en`/`dis`/`prune` скрипт запускает `angie -t` **один раз**
(а не на каждый элемент: конфиг может быть включён раньше модуля, от которого он
зависит, и поэлементная проверка ложно провалилась бы на корректном
промежуточном состоянии). На успехе вывод тихий; при ошибке печатается вывод
`angie -t`, код возврата ненулевой, а изменения по умолчанию остаются на месте
(конфиг, уже сломанный до запуска, не должен блокировать все будущие операции).
Пропустить проверку можно флагом `--no-test` либо указать конкретный бинарь
через `ANGIE_BIN`. Если `ANGIE_BIN` не найден в `PATH`, проверка пропускается с
уведомлением.

Флаг `--rollback` вместо этого откатывает ровно изменения текущего запуска при
провале проверки (удаляет созданные симлинки, воссоздаёт удалённые); его нельзя
сочетать с `--no-test`. Флаг `--reload` запускает `$ANGIE_RELOAD_CMD` (по
умолчанию `$ANGIE_BIN -s reload`) после успешного батча; провал проверки
отменяет перезагрузку.

## Разработка

Типовые задачи собраны в `Makefile`:

```sh
make check          # shellcheck + герметичные тесты (CI-гейт)
make test           # только герметичный набор тестов
make test-container # интеграционный тест против реального angie -t (нужен Docker)
make check-all      # check + test-container
make lint           # shellcheck для shell-скриптов
make lint-md        # линт Markdown-документации (rumdl)
make spell          # проверка орфографии в исходниках (typos)
make install        # установка как angie-ctl в PREFIX/bin (с учётом DESTDIR)
```

`./test.sh` запускает самодостаточный набор на временном дереве `ANGIE_ETC` (не
требует root, установленного Angie или сети; `angie -t` подменяется заглушкой).
`./test-container.sh` дополнительно гоняет **реальный** `angie -t` в официальном
образе Angie, проверяя, что включение через симлинк даёт конфиг, который Angie
принимает; он сам пропускается, если Docker или образ недоступны.

GitHub Actions (`.github/workflows/ci.yml`) запускает `make check` на каждый push
и pull request плюс неблокирующий контейнерный job, который тянет образ Angie и
выполняет `make test-container`.
